# NDL 古籍批量下载工具

`ndl_download.py` 是一个用于从日本国立国会图书馆（National Diet Library，NDL）数字馆藏下载古籍扫描图片的 Python 工具。

它适合用于古籍数字化工作流：

```text
NDL Digital Collections
        ↓
    ndl_download.py
        ↓
    古籍扫描图片
        ↓
     古籍 OCR
        ↓
繁体文本 / 简体文本 / AI 校对
```

本工具的定位非常简单：

> **把 NDL 中可以在线浏览的古籍数字图像批量保存到本地，方便后续 OCR、研究、整理和个人数字化使用。**

---

## 📖 为什么需要这个工具？

NDL Digital Collections 中保存了大量日本国立国会图书馆数字化的历史文献、古籍和图书。

很多资料虽然可以在线逐页浏览，但如果需要：

- 下载整本古籍
- 保存到本地
- 后续进行 OCR
- 批量处理大量古籍
- 建立个人古籍数据库
- 配合 PaddleOCR / PP-OCRv6 做文字识别

手工逐页保存图片会非常麻烦。

`ndl_download.py` 的目的就是把这个过程自动化。

---

# ✨ 功能

当前工具主要用于：

- 从 NDL 数字馆藏页面获取古籍页面信息
- 自动批量下载书籍页面图片
- 按页面顺序保存文件
- 自动创建下载目录
- 支持整本古籍连续下载
- 避免人工逐页保存图片
- 下载后的图片可以直接交给 OCR 程序处理

# 🌐 如何找到 NDL 古籍？

打开日本国立国会图书馆数字馆藏：

https://dl.ndl.go.jp/

在搜索框输入：

```text
书名
作者
关键词
```

例如可以搜索：

```text
山海経
本草綱目
和漢三才図会
```

找到需要的资料后进入数字化内容页面。

---

# 🔗 获取 NDL 页面地址

进入目标古籍的数字浏览页面。

例如：

```text
https://dl.ndl.go.jp/...
```

复制浏览器地址栏中的页面地址。

然后将这个地址提供给：

```bash
python ndl_download.py
```

按照脚本提示执行下载。

# ⚠️ 下载速度

NDL 是公共数字馆藏服务，不建议通过高并发方式对服务器进行大量请求。

如果批量下载：

```text
建议：
低并发
适当间隔
失败重试
避免短时间大量请求
```

尤其不要为了提高速度无限增加线程数。

这个工具应该用于正常的个人研究、数字化和资料整理，而不是对 NDL 服务进行压力测试。

# ⚠️ 下载失败

如果某一本书下载失败，建议首先检查：

### 1. 页面地址

确认输入的是：

```text
https://dl.ndl.go.jp/...
```

对应的数字馆藏页面。

---

### 2. 网络连接

尝试浏览器直接打开 NDL 页面。

如果浏览器也无法打开：

```text
优先检查网络
```

---

### 3. 页面访问限制

某些资料的数字图像可能存在访问条件、利用限制或者只允许特定环境访问。

如果浏览器可以浏览，但脚本无法获取图片：

```text
不要绕过访问控制
```

应检查 NDL 当前页面及利用条件。

---

### 4. NDL 页面结构变化

NDL 网站可能会更新页面结构。

如果以前能够正常下载，后来出现：

```text
找不到页面
无法获取图片
解析失败
```

可能需要更新脚本。

欢迎提交 GitHub Issue。

# 🔍 常见问题

## Q：这个工具是不是下载 PDF？

不是。

它主要面向：

```text
古籍页面图片
```

这样做的主要原因是：

**图片更适合后续 OCR。**

例如：

```text
NDL
 ↓
JPG / PNG
 ↓
PP-OCRv6
```

比先转 PDF 再 OCR 更方便进行页面级处理。

---

## Q：下载后的图片可以直接 OCR 吗？

可以。

推荐使用：

```text
PaddleOCR
PP-OCRv6
```

对于古籍：

```text
繁体中文
竖排
右向左
古籍字体
```

需要特别注意 OCR 排序和人工校对。

---

## Q：能不能自动转换成简体中文？

下载工具本身不负责繁简转换。

推荐把职责拆开：

```text
ndl_download.py
        ↓
负责下载图片

ancient_ocr.py
        ↓
负责 OCR

OpenCC
        ↓
繁体 → 简体
```

这样更加稳定，也方便分别维护。

```text
library/
│
├── 山海经/
│   ├── source/
│   │   ├── 0001.jpg
│   │   ├── 0002.jpg

│   │

│   │   ├── 0001_繁体OCR.txt

│   │

    ├── source/
    ├── ocr/
    └── final/
```

这样以后重新 OCR 或更换 OCR 模型时，不需要重新下载原始资料。

---

# 🔐 原始图片请保留

强烈建议：

> **不要只保存 OCR 后的文字。**

应该至少保留：

```text
原始图片
    +
OCR 原文
    +
简体文本
```

原因很简单：

OCR 永远不是 100% 正确。

例如：

```text
原图：
    某个生僻字

OCR：
    另一个相似字
```

如果原始图片还在，可以重新识别和人工校对。

如果只剩 TXT，就无法判断 OCR 到底识别错了什么。

---

# 🧠 OCR 后不要直接当成正式文本

推荐流程：

```text
图片
 ↓
OCR
 ↓
机器文本
 ↓
低置信度检查
 ↓
人工校对
 ↓
正式数字文本
```

特别是：

- 古籍
- 地方志
- 医书
- 经书
- 家谱
- 历史档案

不要直接把 OCR 输出作为最终出版文本。
